# 独立有限参考验收 v1：实现与历史回放

**已新增可选的独立参考验收入口，拦住 v4 两次模型提取共同误读奇偶规则的测试台。**
72 次历史尝试全部保留：47 份通过给定参考核对、1 份被反例阻断、24 次维持原有弃权。
本批没有新增对既有合格测试台的误拦。结果是已知样例上的验收回归，不是新题泛化实验，
也不代表模型生成正确率提高。

日期：2026-09-26。设计约束见 [实施前协议](../design/bench4hls_reference_gate_v1.md)，
使用说明见 [验收模块文档](../../agent/selftest/BENCH4HLS_REFERENCE_GATE.md)。

## 本轮改变

新增 [bench4hls_reference_gate.py](../../agent/selftest/bench4hls_reference_gate.py)，
可审查已经保存的 v3/v4 草稿，也可通过 `generate_guarded_behaviors` 在 v4 生成后调用。
生成和验收分开保存，参考及验收反例不进入主提取、schema 重试或盲提取提示词。

验收先重编译声明，核对匹配规则、输出约束、执行图、生成收据、实际向量及渲染的 C++。
随后与单独提供、固定外部哈希的有限参考表比较。组合逻辑检查全部输入；状态逻辑探索
可达的“参考状态、生成契约状态”组合，并检查每种输入。差异附带从初态开始的最短输入
反例序列。另对实际输出的全部测试向量进行参考核对。

参考表要求每个状态、每种输入都有且只有一行，所有输出明确给出整数或 `null`。
`null` 表示未知或无约束，不能补成零；对无约束输出强行断言、漏查应检查输出均会失败。
预算不足返回 `inconclusive`，不会将部分搜索标成穷举通过。

只有 `reference_checked` 才导出 `checked/selftest.cpp`，供后续审查；反例、缺参考、
文件不一致或覆盖不足都不导出。检查和导出使用同一份输入快照，原始草稿不被改写。

## 历史回放结果

使用上一轮冻结的 18 个样例和已完成的 v3/v4 `resume1` 结果，每题每版两次。
支持范围内每版 24 次，不支持行为和缺规格每版另有 12 次。参考来自生成之前冻结的
独立评估夹具，不从候选、生成契约或生成向量反推。

| 验收结果 | v3 rules | v4 behaviors |
| --- | ---: | ---: |
| 完整处理的历史尝试 | 36/36 | 36/36 |
| 与给定有限参考一致，导出供审查 | 24 | 23 |
| 发现反例并阻止导出 | 0 | 1 |
| 原生成弃权，继续保留 | 12 | 12 |
| 新增误拦、产物错误、预算不足 | 0 | 0 |

48 份生成草稿中，47 份完成有限模型比较，1 份发现反例；累计检查 1,274 条状态/输入
转移，访问 112 个状态组合。这里是跨多次尝试累加的检查工作量，不是 1,274 个独立
任务或故障。24 次弃权没有被混入生成正确率分母。

唯一反例为 `behaviors/Logic01/run_001`：公开规则是三个输入中奇数个为 1 时输出 1，
模型却写成恰好两个为 1，主提取与盲提取一致。新入口在输入 `[0,0,1]` 找到：

```text
reference result = 1
generated expectation = 0
status = counterexample
export_for_review_allowed = false
```

47 份已核对导出的 C++ 字节与原生验证包中对应的测试台逐一相同。此轮没有修改这些
C++，也没有重跑 C++ 编译或新增 HLS 试验；上一轮执行结果见
[v4 评估](bench4hls_behavior_matching_v4_20260926.md)。

## 验证与可追溯性

新增测试共 **22 项通过**：18 项核心验收测试、4 项回放适配器测试。覆盖同一模型的
共同错误、正确奇偶逻辑、未知初态、复位极性、控制优先级、更新前后观测、多步回绕
错误、比较预算不足、缺参考、错误参考哈希、重复或不完整参考表、带符号数边界、
合法 JSON 中的语义篡改、C++ 篡改、私有参考不进入提示词，以及不覆盖已有输出。

其中，多步回绕测试只保存两个生成刺激，但比较器在更长的输入序列发现错误；它验证
了独立探索能够发现原测试向量未触发的契约错误。适配器测试另检查弃权不被跳过、完整
分母保留、重复结果被拒绝、资格记录绑定和源码快照。

验证命令：

```powershell
python -m unittest tools.test_bench4hls_reference_gate_adapter tools.test_bench4hls_reference_gate -v
```

回放前重新核对原来的 39 项参考/故障实现原生资格记录和对应包、结果哈希。资格属于
既有参考夹具；新有限表由该参考展开，不等于新增了一次全状态域的 C++ 验证。
回放记录冻结了 27 个源码/测试文件；逐项报告、收据、导出文件和原生包对应关系复核
没有发现完整性错误。原 v4 的 22 个冻结源码及 18 个样例仍与旧清单一致。

根代理负责语义策略、核心验收实现、集成修正及结果复核；测试和 CLI/回放适配的重复性
工作按用户要求分派给 gpt-5.6-terra medium。集成期间补齐了弃权处理、完整分母、
参考资格绑定、源码快照和 CLI 导入等问题，均在最终回放冻结之前完成。

## 可用性和限制

这是可选入口，现有默认竞赛路径及 v3/v4 runner 不会自动获得该验收层。它适用于
已有独立小规模参考的任务；没有参考的任意新题仍为 `needs_reference`。

有限参考比较证明的是与该表及 Python 图执行语义的一致性。哈希只固定参考身份，
不认证审核人，也不证明参考正确。来源声明作为 `oracle_provenance_claim` 保留；
评估夹具没有被改标为人工审核契约。所有结果均保持自动候选验收和自动修复关闭。

本轮 **0 次新增真实模型生成请求**，没有 RAG 改动，没有使用 108 道冻结测试题，
没有增加数组、流、浮点或复杂协议支持，没有新增综合、RTL、时序或资源证据。
原有模型服务自动熔断缺口也未在本轮处理。

因此，本轮增强的是误用防护和可执行验收，不据此上调模型语义正确性或泛化评分。
下一轮需要在新的留出样例上分别统计生成正确率、验收误放行、误拦和弃权；不能只报告
验收通过子集的正确率。扩大参考覆盖仍需独立、可审核的参考来源。
