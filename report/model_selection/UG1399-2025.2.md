# UG1399 英文 RAG 第一版实测

完成日期：2026-09-18（2026-09-19 语料升级为 schema v2）。开发分支：`feat/hls-rag`。本轮完成手册建库与独立检索模块；Agent 默认流程尚未接入 RAG。

## 实际产物

- 手册：UG1399 v2025.2 英文版，904 页；895 页生成正文条目，前 9 页封面/目录不入库。
- 语料：587 个有正文的章节，1756 个条目，正文共 1,651,666 字符。保留原文页码、父章节、版本与质量标记。
- 编码输入：384,907 tokens，单条最大 652 tokens，未触发 2048 tokens 上限。
- 模型：原版 Qwen3-Embedding-0.6B，revision `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`，11 个本地文件完成校验。
- 环境：独立 Python 3.12；PyTorch 2.8.0+cpu、Sentence Transformers 5.7.0、Transformers 4.57.6。完整依赖见 [requirements.lock.txt](../../rag/requirements.lock.txt)。
- 向量：1756 × 1024，float32、L2 归一化；矩阵文件约 7.19 MB。CPU 6 线程、batch 8，本轮编码计时 868.141 秒，约 14.5 分钟；不包括模型下载和加载。

原始手册与权重留在用户指定的本地位置；Git 中只保留脚本、版本证据、问题集及检索报告。

## 检索对照

固定同一份语料和 24 条人工开发问题。包括 11 条英文语义问题、7 条符号/API 问题、2 条代码问题、4 条中文问题。运行前确定目标章节标签，未根据排名调整标签。

默认运行预算：每路召回 20，最多返回 3 条，总计不超过 6000 UTF-8 字节。三路都按父章节和文本去重。

| 方法 | Hit@1 | Hit@3 | 平均上下文字节 |
| --- | ---: | ---: | ---: |
| BM25 | 14/24（58.3%） | 18/24（75.0%） | 4165 |
| Qwen 向量 | 15/24（62.5%） | 20/24（83.3%） | 3901 |
| BM25 + Qwen，RRF 融合 | 15/24（62.5%） | 22/24（91.7%） | 4091 |

所有方法的最大返回上下文均为 5884 字节，满足预算。这里不把字节数称为生成模型 tokens。

另一次较宽预算测试（每路召回 30，最多返回 5 条，20000 字节）中，Hit@5 分别为 21/24、23/24、24/24。该结果只表示至少命中一个标注的相关章节，不能解释为所有问题都能正确回答。默认预算与较宽预算的 Hit@3 本轮一致。

默认预算评估中，24 条问题的一次性模型冷加载和批量查询编码合计约 9.5 秒；逐题搜索耗时另存于 JSON。这个时间既不是单次查询延迟，也不包含生成答案或运行 Vitis。

## 值得保留的失败与限制

混合检索在英文“跨调用保存状态”问题上把 `Statics` 排到第二；在 `pipeline` 查询上把对应 pragma 章节排到第一。中文递归问题的 `Recursive Functions` 排到第三，说明向量补回了部分纯 BM25 遗漏。

仍未在前三条命中目标章节的两个问题：

| 问题 ID | 目标 | 当前前三条 |
| --- | --- | --- |
| `stream` | Blocking API / Blocking Read / Write Methods | Deterministic Behavior；stream.size；stream.empty |
| `zh_state` | Statics | RTL Configuration；Continuously Running Mode；Accumulation |

这些是按当前章节标签判定的遗漏，某些邻近章节仍可能含有部分有用信息。没有把标签外结果自动判为完全无关，也没有事后扩大标签来提高成绩。

这份小规模开发集并非独立留出的评测集。章节相关不等于某个条目包含完整答案；跨页代码和表格需要回查父章节。全文图形没有 OCR。PDF 第 125、129、154、547 页经过人工视觉抽查，但全书没有逐页校对。当前没有重排序模型或“不相关”置信阈值。

结果支持保留 BM25 + Qwen 作为下一步 Agent 实验的候选方案，尚不能证明 Agent 修复成功率提高。尤其不能只看 top-1，或把中文检索视为已经可靠。

### schema v1 → v2 迁移（2026-09-19）

原 v1 把 `tool_version` 与 `validation` 写死为常量，只表达单一 PDF 来源。为接入官方示例、库组件与实验案例，语料升级为 schema v2，拆出三个正交维度：

| v1 | v2 |
| --- | --- |
| `tool_version='2025.2'` | `tool.target_version='2025.2'`、`tool.upstream_version='2025.2'`、`tool.measured_version=null` |
| `validation.status='reference_only'` | `release.status='reference'` |
| `validation.hls_validated=False` | `validation.status='unvalidated'` |
| 隐含 `kind='manual_excerpt'` | `kind='document_section'`，新增 `role='doc'` |

本次迁移只改记录信封、不动正文：1756 条记录的 `text`/`content_sha256` 与 v1 逐字节一致，编码输入未变，故 `vectors.npy` 哈希不变，默认预算 Hit@3 不变（BM25 18/24、向量 20/24、混合 22/24）。仅 `records_sha256` 与索引指纹随信封变化。v1 旧哈希：`records.jsonl = bd00aa1331204e759ef6097f9c8267279016fed8804b93ee1394de257ff05633`、索引指纹 `d6a36a639b9bdcc73cd13d6b2872c4e562e9a4411cd3978fbd0e09c867ecc496`。旧语料/索引备份为 `rag/corpora/ug1399-2025.2-en.v1-backup`、`rag/indexes/ug1399-qwen06b-en.v1-backup`（已 gitignore，不提交）。
