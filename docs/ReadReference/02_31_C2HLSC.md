## 一、核心价值

C2HLSC 研究如何借助 LLM，把普通 C 程序改写成 HLS 能处理的代码。其最值得保留的设计思想是：将编译与功能测试、HLS 综合分开检查，并将不同阶段的错误反馈给模型，形成迭代修复流程。

对当前项目而言，本篇可以作为已有 Agent 设计的相关工作和方法依据。用户已确认相关内容完成实现，因此不再将其列为新增实施任务。

## 二、研究内容：人工辅助案例与自动原型

两部分实验采用不同模型，不能混为一个全自动系统的结果。

| 部分 | 模型与任务 | 人工参与和范围 |
|---|---|---|
| 人工参与的案例研究 | Gemini；NIST 随机性测试、QuickSort、AES-128 | 工程师拆分步骤、提供报错、指出问题并补充提示 |
| 自动原型 | ChatGPT 3.5 Turbo；QuickSort 和若干 AES 子函数 | Python 连接模型、GCC 和 Catapult；当时只能处理有限数量的函数 |

作者因没有 Gemini API，在自动原型中改用 ChatGPT 3.5 Turbo。

## 三、方法要点

### 3.1 分步改写

作者将适配任务拆成多个步骤，例如：

- 清理与目标硬件函数无关的打印操作。
- 按应用要求调整数据输入方式和函数参数。
- 将递归转换为迭代，处理受限制的指针与存储结构。
- 调整循环、数组尺寸和数据类型。
- 根据编译、测试和 HLS 工具反馈继续修改。

这些步骤必须服从具体任务约束。论文中的接口调整和计算简化，是相应应用的设计选择；不能因此擅自改变比赛规定的接口或输出语义。

### 3.2 双反馈循环

PDF 第 4 页图 5 展示了自动原型：

```text
候选代码
  → 编译并运行参考测试
      → 失败：反馈编译或功能错误，修改后重试
      → 通过：进入 HLS 综合检查
          → 失败：反馈综合错误，修改后重新检查
          → 通过：得到通过当前验证的候选
```

这里的功能检查依赖测试台及其判定逻辑，不能把“编译通过”直接理解成“功能正确”。为了满足综合要求而修改代码后，也需要重新确认功能。

### 3.3 具体失败证据的重要性

论文指出，编译和综合报错通常较容易反馈给模型；功能错误更难定位，有时需要工程师提供额外上下文。

QuickSort 案例中，模型将递归改成显式栈，但栈管理存在错误，运行时出现段错误。作者提供调试器信息和 `high`、`low` 的中间值后，才逐步修复。

这个案例说明，完成结构改写只是第一步，新引入的状态、容量和索引逻辑仍需要验证。

### 3.4 多轮修改会出现回退

在 QuickSort 案例中，模型按要求将交换操作内联后，后续修改又重新引入了原来的函数形式，需要再次提示。

因此，多轮修复需要持续保留题目约束和已完成修改的必要条件，并依靠回归检查发现新问题。

## 四、实验结果及口径

### 4.1 工具与平台

- Catapult HLS。
- Nangate45 库，50 MHz 目标设置。
- 人工案例通过 ModelSim 仿真检查原 C 与生成 RTL 的结果。
- 作者没有把架构搜索及 pragma 优化作为本文主要目标，相关工作列为未来方向。

上述环境与比赛使用的 Vitis、FPGA 器件和时钟约束不同。

### 4.2 自动原型的提示次数

PDF 第 4 页表 II：

| 任务 | 提示次数 |
|---|---:|
| QuickSort | 6 |
| AddRoundKey | 9 |
| ShiftRows | 1 |
| MixColumns | 1 |
| SubBytes | 1 |

这些是所展示案例的提示次数，不是大规模重复试验得到的通过率。“一次提示成功”的个案不等于稳定的 pass@1 为 100%。自动部分对 AES 按函数拆分，不能据此推断完整复杂工程均可自动处理。

### 4.3 人工辅助开发时间

作者报告，相关 NIST 实现由研究生手工开发约需每项 4 小时，采用 C2HLSC 辅助后约为 30～60 分钟。样本有限，而且这是有人参与的开发时间，不是比赛智能体的单题墙钟时间。

表 I 同时列出资源与延迟结果。不同案例存在差异，不能概括为 LLM 改写在硬件质量上全面优于人工实现。

## 五、阅读时需要注意的限制

1. **任务起点不同。**本文从已有 C 程序出发；比赛还包括从题目生成初始候选的步骤。
2. **接口与功能不能任意简化。**部分 NIST 案例把整批输入改成流式输入，并将具体 p-value 计算改为阈值判定。只有应用需求允许时，这类改动才成立。
3. **指针不是一律不可用。**应按实际用法和目标工具的限制判断，不能把案例中的去指针步骤当作通用禁令。
4. **代码展示仍需核查。**PDF 第 3 页把绝对值阈值判断的预期表达式写成了明显不正确的条件。对于非负阈值 `T`，数学上 `|sum| <= T` 对应 `-T <= sum && sum <= T`；具体代码还需保证类型及表达式求值正确。附录第 5 页示例采用了相应的上下界判断。
5. **测试覆盖有边界。**通过给定测试不能自动证明所有合法输入上的等价性。
6. **论文证据规模较小。**人工辅助案例和自动原型应分别评价；本文主要证明方法具有可行性，未给出当前本地模型在比赛题集上的成功率。
