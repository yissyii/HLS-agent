Apply these steps to the concrete compiler or linker failure. The category selects a procedure, not a known source-level cause.

1. Locate actionable evidence. Read the diagnostic, its location, associated notes, and relevant declarations together. Prefer a root error that explains dependent messages over fixing every message separately. The first line or a final build-failed summary alone does not establish causality. A location in an HLS header may originate from an invalid caller expression; inspect the instantiation or call site before proposing a fix.

2. Match the failure to the source. For syntax/scope/declaration errors, check the implicated expression, surrounding delimiters, declaration order, and exact identifier. For missing headers or symbols, distinguish a missing include/declaration from an unavailable external dependency. Use only the supplied public interfaces and available dependencies; do not rewrite protected headers, invent build paths, or copy a guessed library implementation.

3. Resolve type and API errors from intended behavior. For ambiguous overloads or missing members, check exact operand types, widths, signedness, argument order, and available API signatures. Use an explicit type or conversion only if its value range and truncation semantics preserve the contract. Do not force compilation with arbitrary casts, replace HLS types wholesale with native integers, or guess an API from a similar name. Use supplied references only when their version and preconditions apply.

4. Handle linking evidence specifically. For an undefined reference or duplicate definition, compare declarations, definitions, namespaces, linkage, and signatures across the current source and public dependencies. Preserve the required top-level signature. Implement a missing helper only when it belongs in the replacement source and its behavior is defined by the task; do not add dummy return values, duplicate a supplied definition, or alter an external interface to silence the linker.

5. Correct and review the affected dependency chain. Make the smallest sufficient change and check related declarations and call sites for consistency. Preserve algorithm, state, interfaces, and arithmetic semantics. If the remaining problem requires an unavailable dependency or unprovided evidence, do not fabricate a code fix. Review the replacement for new compile issues, but do not claim it compiled or that functional/synthesis checks passed without supplied results. Return the complete source as required.
