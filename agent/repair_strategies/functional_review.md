# 功能策略审阅 v0.1.1

本文件用于协作审阅，不参与模板加载。案例均为合成，尚未调用模型验证效果。

新版按六步组织：明确题意、核对证据、追踪错误输出、按需检查状态时序、修改、复核。最小充分修复可以涉及多个关联变量，不以修改行数最少为目标。

## 审阅案例与预期

1. **中间结果截断**：题目要求两个无符号 8 位数相加，保留 9 位结果。代码先存入 8 位临时变量；输入 255、1，期望 256，实际 0。应检查表达式与中间存储宽度，仅扩大最终输出不能恢复进位。若题意要求 8 位回绕，则不适用这个修法。

2. **同时更新误写成顺序依赖**：题目要求 a_next=b_old、b_next=a_old，代码为 `a=b; b=a;`。旧状态 1、2，期望新状态 2、1，实际 2、2。应从正确旧值计算后再提交，并检查关联输出；不能推广为所有赋值都必须用旧值。

3. **reset 被 enable 挡住**：题目要求每次调用 reset 优先于 enable，代码却把 reset 放在 `if(enable)` 内。应修正条件优先级并保留正常更新与保持分支。案例没有定义物理异步复位，不能擅自增加时钟边沿检测或接口。

4. **只有 cycle 和结果**：`Mismatch at cycle 4: expected 7, got 3`，缺少输入和历史。应核对题意与源码，不认定错拍、不编造前四拍轨迹。有明确题意违例仍可修；没有依据时不随意加延迟。

5. **只有非零退出摘要**：不能认定越界、除零或死锁。仍路由到 functional，但应走模板中的保守检查。策略类别不等于已经确认根因。

6. **事务被标成 cycle**：一次调用处理完整数组，测试把第四个事务标为 cycle 4。应检查数组计算，不新增跨调用状态或改成每次调用只处理一个元素。

## 尚待验证

这些案例用于人工检查指令歧义，不证明模型会按预期修复。后续应固定开发任务首稿、反馈、参考资料和预算，对比统一提示词与分类策略，并实际运行 csim 和 synthesis。

证据不足且找不到题意违例时，策略允许保留源码；将来接入现有控制器可能触发 repeated_candidate。应单独统计，再决定是否追加诊断或换策略，不在本轮同时改变停止机制。
