# v0.2：有界采样与独立判据审核

## 审核器 0.2.1 补丁（2026-09-23）

测试包版本保持 0.2.0，审核报告改为 schema_version=2，并新增 auditor_version=0.2.1。
只有 audit 默认预算改为 65536，覆盖当前规则支持的完整 1～16 位单输入域；generate 默认预算仍为 4096。
显式传入较小 --max-cases 不会被覆盖；例如下文的 --max-cases 4096 对 16 位仍然是抽样。
主输入预算不包含补充性质的额外求值，总求值次数仍见 oracle_evaluations。

- 非对象规则／锚点附件（例如 [] 或 null）正常返回 inconclusive，并保存原附件及哈希。
- evidence_scope 区分 none、supplied_anchors、sampled_rule、full_domain_rule；只在相应检查完整结束后标记范围。
- audit_complete 表示本轮计划检查完成，不表示题意已核验；中途异常时保持 false。
- conclusion 为便于阅读的条件性结论；所有结果仍带 manual_review_required=true、automatic_repair_allowed=false。
- binding_semantics 始终为 not_independently_verified；未实现自动规则语义验证。
- supported/conflict/inconclusive 与 CLI 退出码保持原约定。退出码 0 不是正式正确性证明，也不是自动修复授权；新增字段是报告约定，不是已经接入主流程的强制门禁。


状态：仍为独立实验模块，未接主流程。默认 `generate` 保持 strict 策略，v0.1 冻结包可读取。
本版不新增自动修复、不增加辅助模型、不把审核结果当成官方正确性。

## 有界采样

```powershell
python -B -m agent.selftest generate problem.txt interface.h output/new_suite --config serve/runtime.json --planning-policy bounded-v2 --max-cases 4096
```

也可用 `--response-file` 回放旧响应；回放不是新模型评测。

- 在任何采样前校验所有显式案例、规则引用和类型，不能靠删掉不合法用例使计划通过。
- 仅对 bool 参数将 JSON true/false 规范化为整数；其他参数严格拒绝 bool、字符串或浮点。
- 显式用例去重后必须全部保留，显式用例本身超预算仍失败，不擅自删减。
- 声明输入域大小不超过预算时穷举。大空间采用边界＋固定种子随机。
- 全部边界组合装不下时，用固定种子抽取边界子集，预留部分预算给随机；可能缺失重要边界，必须读实际覆盖记录，不能宣称边界全覆盖。
- 随机次数受剩余预算限制。重复抽样有尝试上限，实际数量可能不足，均如实记录。
- `requested_plan.json` 保存原模型计划；`planning.json` 保存调整原因、布尔转换位置、实际采样方式、每条向量来源。`test_plan.json` 是程序展开后的 schema-v2 显式计划。
- 新增文件一并计入 suite 哈希；load_suite 会重新运行采样策略、表达式和渲染器，不只检查文件存在。
- 旧 strict 包不改动。v0.2 包不能要求旧 v0.1 读取器识别。

## 判据审核

```powershell
python -B -m agent.selftest audit output/new_suite output/new_audit --binding binding.json --max-cases 4096
```

规则库第一批仅有 `gray_decode`、`reverse_bits`、`popcount`，支持单个无符号输入、完整 1～16 位输入域和可容纳结果的无符号返回值。库由本次开发编写并有算法对照回归，**尚未经过其他队员独立人工审核**。

不按函数名自动选规则。调用者必须明确指定绑定，提供套用规则的公开依据：

```json
{
  "schema_version": 1,
  "suite_id": "从 inspect 输出中获取",
  "rule_id": "gray_decode",
  "width": 8,
  "evidence": [{"source": "problem", "quote": "题面中的逐字原文"}]
}
```

这份引用只能证明来源，不能证明选用规则正确。类型与输入域适配由程序检查，语义适配仍需人审。
审核检查规则锚点、算法对照以及补充性质（Gray 逆编码、位反转两次、互补输入置位计数和）。
主输入点数不超过 max_cases，补充性质可能额外执行判据；`oracle_evaluations` 记录总执行数。不调用模型或 Vitis，不读候选实现。

也支持仅提供锚点，使用 `--anchors anchors.json`，不能和 `--binding` 同轮混用：

```json
{
  "schema_version": 1,
  "suite_id": "从 inspect 输出中获取",
  "anchors": [{"inputs": [1], "expected": 1,
    "evidence": [{"source": "problem", "quote": "题面中的逐字原文"}]}]
}
```

外部锚点也是调用者提供的证据，不自动视为人工审核或官方答案。

| 状态 | 含义 | CLI 退出码 |
| --- | --- | --- |
| supported | 本轮检查支持判据，仅相对于提供的规则／锚点 | 0 |
| conflict | 存在可复查的不一致，不自动判定责任方 | 1 |
| inconclusive | 没有证据、规则不适用、预算不足、异常等 | 2 |

即使穷举全部输入，也不发布 `verified_under_spec` 或“已证明符合题意”。所有结果保留 `binding_semantics=not_independently_verified`。
冲突不授权修复候选。新报告记录 suite_id、审核代码哈希、规则版本、证据副本、测试范围和前 20 条反例；原测试包不修改。
没有人工复核前，审核只能用于旁路分析。用户提交了错误规则绑定，同样可能造成误报。
