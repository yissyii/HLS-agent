# 独立规则推荐模块 0.1.0

这是题面到规则的建议层，不是规则审批器，也不接主流程。

## 输入与输出

仅接收公开题面、接口及现有规则注册表。没有候选代码、生成判据、参考答案、官方测试台或审核反馈输入。

模型只能提出三种决策：

- `propose`：建议一条现有规则，给出位宽、完整输入域、原文依据、理由。
- `unsupported`：任务行为或接口条件超出现有规则库。
- `uncertain`：题面缺少决定性信息，需要澄清。

后两种决策的 `rule_id`、`width`、`input_domain` 必须全部为 null；不能一边说不确定，一边提供可执行绑定。

程序检查 JSON 结构、规则 ID、位宽、参数数量、类型范围、完整输入域、返回类型及原文引用存在性。`propose` 不得含未解决疑点。所有决策必须提供题面引用；仅引用函数签名不能支持行为判断。

程序不能证明模型提出的输入域或规则确实由题意推出。即使格式和结构检查通过，仍输出：

```json
{
  "status": "recommendation_unreviewed",
  "semantic_match": "unverified",
  "manual_review_required": true,
  "automatic_binding_allowed": false
}
```

上述字段同样适用于结构合法的拒绝／不确定答复。`recommendation_unreviewed` 表示收到可复查的建议，不代表建议内容正确。结构非法或模型请求失败时，状态为 `failed`。

## 使用

在项目根目录：

```powershell
python -B -m agent.selftest.recommend problem.txt interface.h output/new_recommendation --config serve/runtime.json
```

单次最多一次模型调用；复用既有传输层。严格评测要求环境没有开启传输重试策略，实验脚本会检查这一点。模块本身没有另建修复／重试循环。

离线回放：

```powershell
python -B -m agent.selftest.recommend problem.txt interface.h output/replayed_recommendation --response-file proposal.json
```

每次使用新目录。保存公开输入、实际提示词、原始响应／请求记录、解析后的提议、结构校验结果及指纹。离线回放不是模型能力评测。

## 人工复核清单

1. 题目要求的操作、方向和范围，是否与整条规则一致？编码不等于解码，换字节不等于反转位。
2. 位宽来自题面还是被存储类型误导？是否处理前导零、完整字还是局部字段？
3. 所有合法输入是否保留？不得缩小输入域来强行适用规则。
4. 是否有符号、溢出、返回范围、额外参数、跨调用状态、reset 或流顺序要求？
5. 原文引用是否真正支持结论，而不仅是“在题面中找得到”？
6. 至少手算一两个能区分候选规则的例子。例子来自题意，不从待检查实现复制。
7. 对不上时选不适用；缺信息时选不确定，不为提高通过率强行匹配。

本版没有人工签署或批准文件机制；只有未审核建议。不要自行把 `proposal.json` 改名为审核绑定后用于生产自动修复。

## 内部评测协议

`tools/prepare_rule_selection_study.py` 创建 20 道作者自编题：12 道适用、4 道易混淆、4 道不支持。公开目录仅有题面和接口，参考标签与独立 C++ 参考输出存于 private 目录。

`tools/run_rule_selection_study.py generate` 冻结代码／提示词／参数后执行生成阶段。规则推荐和测试台生成互不传递输出，每题最多 3 次模型请求，总计最多 60 次；最多两个任务并发，无实验重试。生成程序不加载私有参考标签，只在清单中记录私有文件指纹。

`evaluate` 要求全部任务生成结束，先固定成功测试包和建议，再加载参考标签评分。模型建议仅在评分实验内用于条件性审核；这不是经过人工批准的生产绑定，也不会触发代码或测试台修复。

各项分开统计：建议是否正确、原始错误建议是否被结构校验拦截、生成失败／主动拒绝、判据全域数学正确性、输入域是否被改动、条件性审核结果与模型请求数。未知状态和失败不从任务分母中删掉。

本轮是内部新题措辞／位宽试验，三类数学家族已知、题目与程序出自同一开发方。不是第三方盲测，也不能保证模型训练未见类似任务。参考程序需要队友独立复核。数值评分不等于 Vitis 综合或 RTL 时序正确性。
